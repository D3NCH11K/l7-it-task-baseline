# ЛР7 – Baseline классификатора IT-задач

Репозиторий содержит воспроизводимый baseline для проекта классификации синтетических текстов IT-задач по направлениям FrontEnd, BackEnd, QA, DevOps, ML и UI/UX.

## Baseline и постановка

Используется частотный классификатор: он всегда выбирает самый частый класс из train. Методические указания ЛР7 допускают частотный класс как baseline для классификационной задачи. Текст не подаётся модели, validation и test не используются для выбора класса.

## Данные

В `tasks_dataset.csv` находятся 2 333 синтетические записи. По сведениям владельца набора, метки сформированы по промптам и проверены; чувствительных данных нет. Исходный SHA-256: `90859af964559d1140fec298bf0b4f70e725dac3e7813e2062b2ea50fe9dfdf2`.

При подготовке удаляются точные дубли по нормализованному тексту (`strip`, `casefold`, схлопывание пробелов). Остаётся 2 061 запись; конфликтов меток для одинакового текста нет. Разбиение стратифицировано: 70/15/15, `seed=42`. Части не пересекаются по ID нормализованного текста. Самый частый класс train – `QA` (395 из 1 442).

## Установка и запуск

Нужен Python 3.13. Установите зафиксированные зависимости и запустите baseline из папки проекта:

```powershell
python -m pip install -r requirements.txt
python baseline.py --data tasks_dataset.csv --output results
```

Для Colab загрузите CSV в `/content` и выполните:

```python
from baseline import run_baseline
summary = run_baseline('/content/tasks_dataset.csv', '/content/lr7_results')
```

Скрипт проверяет SHA-256 исходного файла и останавливается, если источник отличается. Выходные файлы создаются в `results/`.

## Результаты validation

Baseline оценивался только на 309 validation-примерах. Test (310 строк) не оценивался и не участвовал в выборе.

| Метрика | Значение |
|---|---:|
| Accuracy | 0.2751 |
| Balanced Accuracy | 0.1667 |
| Macro F1 | 0.0719 |
| Weighted F1 | 0.1187 |

Классификатор верно определяет все 85 примеров класса QA и ошибается на 224 примерах пяти других классов. В `results/validation_predictions.csv` сохранены все 309 случаев; отдельные файлы содержат 10 корректных и 10 ошибочных примеров. Есть также метрики по каждому классу и confusion matrix.

## Файлы

- `baseline.py` – standalone модуль, CLI и функция `run_baseline`.
- `requirements.txt` – закреплённые версии библиотек.
- `settings.json` – протокол эксперимента и фиксированные параметры.
- `environment.json` – фактические версии Python и библиотек при запуске.
- `results/metrics.csv`, `results/per_class_metrics.csv`, `results/confusion_matrix.csv` – оценки.
- `results/validation_predictions.csv` – все validation-примеры.
- `results/successful_cases.csv`, `results/error_cases.csv` – подборки 10+10.
- `results/run_summary.json` – сводка запуска.

## Ограничения и следующая гипотеза

Результат показывает качество только относительно синтетических промптных меток; он не доказывает перенос на реальные IT-задачи. В данных нет ID автора, источника или серии генерации, поэтому возможное сходство шаблонов между split исключить нельзя. Следующая гипотеза для ЛР8 – сравнить этот baseline с TF-IDF + Logistic Regression по Macro F1 и Balanced Accuracy; настройки выбирать на train/validation, test открыть один раз после фиксации решения.
